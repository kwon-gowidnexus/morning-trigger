# morning-trigger

아침 보고 정시 요청기. `kwon-gowidnexus/claude`의 아침 보고 워크플로 세 개를 서울 시각 정시에 `workflow_dispatch`로 요청한다.
외부 예약 서비스 없이 GitHub 안에서만 돈다 (2026-10-28).

| 대상 워크플로 | 정시 (KST) |
|---|---|
| `daily-fortune.yml` | 06:30 |
| `newsletter-digest.yml` | 07:00 |
| `checkpoint-reporter.yml` | 08:00 |

## 왜 이렇게 하나

- GitHub 정기 실행(`schedule`)은 늦게 뜬다. 하루 한 번짜리도 79~289분 늦었고(2026-10-27, 최근 30회), 자주 뜨는 예약은
  대기열에서 버려져 간격과 무관하게 하루 2~3회만 뜬다(5분·15분·20분 간격 모두, 2026-10-26~28 실측).
- 그래서 시각은 '기다림'으로만 맞춘다. 이 저장소의 작업이 KST 02:30 예약으로 떠서(실제 기동 03:49~07:19) 정시까지 잠든 뒤
  요청한다. 요청은 예약과 달리 몇 초 안에 시작한다.
- 공개 저장소라 대기 시간이 무료다. 비공개 저장소에서는 대기 시간이 월 2,000분 한도에 잡힌다.

## 동작 (`trigger.py`)

대상마다 정시 순으로: ① 오늘(KST 0시 이후) 진행 중이거나 성공한 실행이 있으면 건너뜀 → ② 정시 전이면 정시까지 잠들고 깬 뒤
①을 다시 확인 → ③ 요청(ref=main) 뒤 60초 안에 새 실행이 생긴 것을 확인. 실행 목록을 못 읽으면 '오늘 실행 없음'으로 보고
요청한다(중복은 대상 워크플로의 같은 날 가드가 막는다). 종료 코드 0 정상 · 1 요청 실패 있음 · 2 토큰 없음.

수동 실행 입력: `now`(기다리지 않고 바로 판단·요청) · `force`(오늘 실행 여부와 무관하게 요청, 검증용) · `targets`(일부 대상만).

## 비밀값·운영

- `MORNING_TRIGGER_TOKEN`: `claude` 저장소 한정, Actions 읽기/쓰기 권한의 세분화 토큰(fine-grained PAT). 만료일은
  `claude` 저장소의 메모리(`reference_morning_trigger_repo.md`)에 적는다. 만료 전에 새로 발급해 비밀값을 갈아 끼운다.
- 공개 저장소는 60일 동안 활동이 없으면 예약이 자동으로 꺼진다. 작업이 끝날 때마다 `activity.log`에 한 줄을 커밋해 활동을 남긴다.
- GitHub 예약이 통째로 멈춘 날(2026-10-13)은 이 작업도 뜨지 않는다. 그런 날은 `claude` 저장소의 `morning-heartbeat`와 각 워크플로의
  예비 cron이 늦게나마 보낸다.
- 예약을 늦추면(예: KST 03:30) 대기는 줄고 늦게 깨는 날의 지연은 는다. `.github/workflows/morning-trigger.yml`의 cron 한 줄과
  `tests/test_trigger.py`의 덮개 검사를 함께 고친다.
